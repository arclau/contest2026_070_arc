# AI 长周期项目记忆体系（AGENTS.md + DevLog 节点索引）

## 何时用这套技能

- 多会话 AI Coding 的长周期项目（周级~月级），需要跨会话保持上下文不丢。
- 项目文档散乱、AI 每次会话都要重新摸索、重复踩同一个坑。
- 需要向第三方（评委/审计/接手人）证明开发过程真实可溯。

## 核心思想

**用两个文件把 AI 的"工作记忆"外置到仓库里**，每次会话按固定顺序加载，控制上下文预算：

```
① AGENTS.md     —— 环境事实 + 硬纪律 + 当前唯一焦点（每次会话必读，≤14KB）
② devlog.md     —— 节点索引表：每行 = 一个节点（日期/P号/结论/固化tag/详情链接）（≤80行）
③ devlogs/*.md  —— 按需读的排障详情（唯一事实源，索引里禁止展开过程）
```

关键取舍：**索引只存结论，过程下沉到子文档**。AI 扫一眼索引即可定位进度，需要细节才点开子文档——上下文花费从 O(全项目) 降到 O(1 页)。

## AGENTS.md 怎么写（六要素，按顺序）

1. **文档读取协议**：开头写死"先读我 → 再读索引 → 按链接读详情"，禁止 AI 跳层或在大文件里翻过程。
2. **环境写死**：构建命令、产物路径、工具链版本——表格化，AI 不用再探索。
3. **源码地图**：每个文件一行职责（改 X 直接去 Y 文件），禁止全仓搜索。
4. **当前焦点（唯一）**：永远只有 1 个最高优先目标 + 已闭环清单 + 待办。**这是会话开始的第一上下文**。
5. **已知坑**：每条 ≤200 字符，只写"现象→根因→对策"，按日期淘汰旧坑。**每新增一条必须删一条**。
6. **维护硬限**：字节数/行数上限表，超限先删再写——没有上限的交接文档会在两周内膨胀到没人读。

## DevLog 节点索引怎么维护

- **一行一节点**：`| P216 | ✅ 修复6项崩溃挂死：... | tag | 详情→子文档 |`，单行 ≤120 字符。
- **P 号单调递增**：全局事件编号，跨会话引用的唯一锚点（"P214 修过尾音"比"那天修的尾音"可查）。
- **状态标记**：✅闭环 / ⏳待上板 / ⚠️挂起，与会话结论同步。
- **固化 tag**：每次可验证里程碑（编译打包通过/上板验证通过）打 git tag，节点表记录 tag 号——**tag 数 ≈ 真实迭代次数**，过程可审计。
- **超限归档**：节点表超过 80 行，最早 10 行移入 `archive/devlog_archive_<范围>.md`，链接保留。

## 每次会话结束的固定动作（只改两处）

1. 节点表首行加新节点（或更新）
2. AGENTS.md「当前焦点」概要刷新（≤10 行）

其余详情写进当日 `devlogs/<M-D>partNdevlog.md`。**禁止在索引文件里写排障过程**——那是子文档的职责。

## 排障方法论沉淀（可选进阶）

把反复出现的排查套路抽成独立 methodology.md（按需加载，非每次必读），例如：

- 寄存器差异定位：差异位可能是果不是因，先确认属性再动手
- 状态机生命周期：关外设要关状态机，不只关使能位
- 后台化四问：指针清了吗 / timer 判空了吗 / 状态单源吗 / 会双开吗

## 落地检查清单

- [ ] AGENTS.md ≤14KB 且有硬限表
- [ ] 节点索引 ≤80 行、单行 ≤120 字符
- [ ] 每个节点有：P号 / 结论加粗 / 固化tag / 详情链接
- [ ] 索引里搜不到排障过程（过程只在子文档）
- [ ] 会话结束只改两处：节点表首行 + 焦点概要
- [ ] 旧内容归档不删除（archive/ 目录，可回溯）

## 本项目的实例

见 `docs/AGENTS.md`（交接协议实例）与 `docs/devlog.md`（节点索引实例）+ `docs/devlogs/`（79 篇子日志）：3 周 216 节点、578 次固化 tag，跨约 80 个会话无上下文丢失。
