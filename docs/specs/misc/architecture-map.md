## 当前结构

| 层/职责 | 文件 | 修改前关注 |
|---|---|---|
| 启动、设备与主循环 | `luncher_dm.c` | 初始化顺序、有效配置、首次刷新、loop；现有临时诊断见 P253 |
| 页面视图 | `ui/ui_home.c`、`ui/ui_*.c` | 完整构建函数、事件、timer、销毁与返回路径 |
| 主题与尺寸 | `dm_theme.h/.c` | 720×360 逻辑单位 ×2，资源根、颜色/材质；字号为物理像素，勿重复缩放 |
| 共享 UI/播放协调 | `deskmate_ui.h/.c` | 构建器、字体、弹窗、播放等仍耦合；C 文件约 3666 行（审计时），不是纯视图层 |
| 网络/天气/健康/语音 | `dm_net.*`、`dm_weather.*`、`dm_health*`、`dm_ai.*`、`dm_voice.*` | 异步回调、状态所有权、线程与 UI 交界；存在文件分离不等于线程安全 |
| 宠物 | `dm_pet.*`、`pet_core.*`、`pet_view.*`、`pet_frames.*` | 模型/视图/资源帧生命周期；不再以旧内置 `pet_cat_*` 为准 |
| 硬件对接 | `dm_ld2410b.*`、`dm_als.*`、`dm_uart_dbg.*` 与 vendor/nuttx 驱动 | 真实板级依赖，goldfish 不能验证外设 |
| 模拟后端 | `sim/dm_net_sim.c`、`sim/dm_sim_stubs.c`、`sim/stubs/` | 假状态/空实现只证明 UI 流程，不证明网络/音频硬件功能 |
| 构建入口 | `sources.txt`、`Makefile`、`CMakeLists.txt`、`Kconfig` | 公共 C 文件只加 `sources.txt`；平台差异在入口分支，不维护两份 UI |

`common/README.md` 明确仍是拆分占位；不能把该目录存在视为 P3 完成。应用旧 README 的屏幕/字体/帧资源说明有历史信息，当前尺寸与硬件状态以 AGENTS、ROADMAP、代码为准。

## 增量改动边界

期望依赖方向：页面 → 业务接口 → 平台实现。主题为页面提供 token/构建器；后台结果经项目已有的同步/事件机制送入 UI 上下文。

- 页面应使用 `dm_net.h` 等业务接口，避免直接引入板端 HAL 头；相关冲突历史见 P247。
- 回调、线程、timer 的拥有者必须清楚：谁创建、谁取消、谁写状态、页面关闭后谁仍存活。不能靠在所有函数加空指针判断替代生命周期修复。
- stub 必须仅在 SIM 目标选中。板端核对 `CONFIG_LUNCHER_DM_SIM` 未开启；模拟器的假成功不计入实机验收。
- 共享结构/ABI 的配置必须一致。`-D CONFIG_LUNCHER_DM_SIM=1` 是当前 CMake 的局部兼容措施，不证明内核、LVGL、应用全部读取同一配置。
- 先用当前结构复现与修复，再按真实变更需要提取单个边界；没有复现/验收基线时不开展全应用重写。

## 下一阶段的拆分顺序（待实施）

1. 稳定启动、首刷、输入和一次页面往返，建立可复现基线。
2. 先检查 SIM/BOARD 配置与链接清单是否互相污染，收口平台适配入口。
3. 当播放或字体相关需求触及 `deskmate_ui.c` 时，再提取对应服务/资源管理接口，一次只拆一个职责。
4. 每次提取保留调用方行为，验证创建、关闭、重开及异步返回。不要为满足目录命名一次搬完全部文件。

验收规则统一见 [开发流程](development-workflow.md)。
