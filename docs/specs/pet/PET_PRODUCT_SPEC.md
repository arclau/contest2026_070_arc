## 一、产品定位

**一句话**：住在锁屏里的小生命，不是锁屏上的动画装饰。

**核心理念**：
- 它本来就在这里生活，用户只是偶尔来看看
- 用户不理它，它自己玩；用户摸它，它回应
- 它不惩罚用户，不死亡，不强制打卡
- 它是健康助手的"情绪化人格出口"

**硬件约束**：R528 Cortex-A7 + 128MB DDR3 + 1920x1200 MIPI LCD + LVGL 9.x

## 二、宠物种类

### 猫（默认/第一只）

| 属性 | 值 | 说明 |
|------|------|------|
| 性格 | 傲娇、好奇、慵懒 | 不会主动讨好，但会偷偷看你 |
| 互动倾向 | 被动为主 | 你摸它才理你，不摸它可能背对你 |
| 饥饿速度 | 慢 | 猫本来就吃得少 |
| 精力消耗 | 中 | 白天慵懒，晚上活跃（猫头鹰习性） |
| 快乐来源 | 抚摸 > 投喂 > 玩耍 | 猫更享受被摸 |
| 睡眠习惯 | 频繁短睡 | 一天睡很多次，每次不长 |
| 特殊行为 | 玩尾巴、舔毛、看窗外 | 随机触发，无实际功能 |
| 食物偏好 | 鱼(+高快乐) > 零食(+中) > 普通 | |

### 狗

| 属性 | 值 | 说明 |
|------|------|------|
| 性格 | 热情、活泼、黏人 | 会主动跑过来，会期待你摸它 |
| 互动倾向 | 主动为主 | 看到用户就兴奋，长时间不理会委屈 |
| 饥饿速度 | 快 | 狗吃得多 |
| 精力消耗 | 高 | 动来动去，消耗大 |
| 快乐来源 | 玩耍 > 投喂 > 抚摸 | 狗更爱玩 |
| 睡眠习惯 | 集中长睡 | 晚上一大觉 |
| 特殊行为 | 摇尾巴、追球、叼东西 | 随机触发 |
| 食物偏好 | 肉(+高快乐) > 零食(+高) > 普通 | |

**关键**：猫和狗是两个不同性格的宠物，不是两个皮肤。行为权重、情绪曲线、互动反馈完全不同。

## 三、核心属性系统

### 基础属性（6个，全部有实际表现）

| 属性 | 范围 | 初始值 | 衰减速率 | 表现 |
|------|------|--------|----------|------|
| **Hunger** 饥饿 | 0~100 | 50 | 猫-1/h, 狗-2/h | 低→没精神、看向食物、撒娇 |
| **Energy** 精力 | 0~100 | 80 | -0.5/h（醒时） | 低→打哈欠、动作变慢、找地方睡 |
| **Happiness** 快乐 | 0~100 | 60 | -0.3/h | 低→动作减少、表情低落；高→主动跑跳 |
| **Affection** 亲密度 | 0~100 | 20 | 0（不衰减） | 只增不减，代表与主人的羁绊 |
| **Health** 健康 | 0~100 | 100 | 间接（hunger<20时-1/h） | 低→无精打采、动作迟缓 |
| **Growth** 成长 | 0→∞ | 0 | 0（只增） | 累计互动次数，驱动生命周期 |

### 属性联动规则

```
Hunger < 20  → Health 每小时 -1
Energy < 10  → 强制进入 SLEEP 状态
Happiness < 20 → 减少随机行为触发
Hunger > 80 && Happiness > 80 → 特殊行为概率 +50%
```

## 四、生命周期

```
幼年（Growth 0~99）
  ↓ 体型小、动作幅度小、好奇心强
成长（Growth 100~499）
  ↓ 体型中等、行为更丰富
成年（Growth 500+）
  → 体型完全、性格稳定、特殊行为解锁
```

- **不做死亡**：宠物永不死亡，这是 Companion 不是 Tamagotchi
- **不做惩罚**：长时间不理它 → 它想念你 → 情绪略低 → 你回来 → 它开心欢迎
- **离线时间**：重启后根据 elapsed_time 更新属性，但设下限（hunger 最低20、happiness 最低30）

## 五、行为系统（Behavior System）

### 架构：State → Behavior → Animation → Duration → Next

每个状态下有多个可选行为，按**随机权重**选择：

```
State: IDLE
  ├─ look_left      20%    看左边
  ├─ look_right     20%    看右边
  ├─ yawn           10%    打哈欠
  ├─ stretch         8%    伸懒腰
  ├─ sit            15%    坐下
  ├─ wander         12%    小范围走动
  ├─ play_tail       5%    玩自己的尾巴（猫专属）
  ├─ chase_ball      5%    追球（狗专属）
  ├─ notice_user     3%    突然发现用户，看向屏幕
  └─ special         2%    特殊动作（成年解锁）
```

### 状态枚举（MVP 10个）

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| IDLE | 默认待机 | 无特殊事件 |
| WANDER | 小范围移动 | IDLE 随机触发 |
| PLAY | 玩耍中 | 用户点击/拖拽/投喂玩具 |
| EAT | 吃东西中 | 用户投喂 |
| SLEEP | 睡觉 | Energy<10 或深夜自动 |
| HAPPY | 开心 | 喝水/起立/目标达成 |
| SAD | 不开心 | Hunger<20 或长时间不理 |
| HUNGRY | 饥饿 | Hunger<30 |
| CURIOUS | 好奇 | 天气变化/音乐播放/新事件 |
| CELEBRATE | 庆祝 | 健康目标达成 |

### 时间联动

| 时段 | 行为倾向 |
|------|----------|
| 早晨 (6-10) | 醒来、伸懒腰、打哈欠 |
| 白天 (10-18) | 正常活跃，偶尔慵懒 |
| 傍晚 (18-22) | 开始犯困，行为变慢 |
| 深夜 (22-6) | 强制 SLEEP，不主动打扰 |

### 天气联动（增强表现，不改核心数值）

| 天气 | 表现 |
|------|------|
| 晴天 | 稍微开心（happiness+1/h） |
| 下雨 | 看窗外、变懒 |
| 高温 | 没精神、趴着 |
| 寒冷 | 蜷起来 |

### 音乐联动

```
music_playing == true
→ 随机触发"摇摆"行为（概率 5%/tick）
→ 不需要音频分析，只看状态
```

## 六、互动系统

### 触摸互动（核心玩法）

| 手势 | 宠物反应 |
|------|----------|
| 轻点身体 | 回头看你（猫可能慢半拍，狗立刻转头） |
| 轻点头部 | 开心、蹭手（猫）/ 摇尾巴（狗） |
| 长按 | 进入抚摸模式，Affection+1 |
| 连续点击3次 | 有点烦、躲开（猫）/ 以为在玩（狗） |
| 快速连续5次 | 进入玩耍状态 |
| 拖拽 | 宠物跟随触摸点移动（玩耍） |

### 投喂系统

| 食物 | 猫效果 | 狗效果 | 获取方式 |
|------|--------|--------|----------|
| 🐟 鱼 | Hunger-30, Happy+20 | Hunger-20, Happy+10 | 默认可用 |
| 🍖 肉 | Hunger-20, Happy+10 | Hunger-30, Happy+20 | 默认可用 |
| 🥕 蔬菜 | Hunger-15, Happy+5 | Hunger-15, Happy+5 | 默认可用 |
| 🍪 零食 | Hunger-10, Happy+25 | Hunger-10, Happy+30 | 成长解锁 |

**交互流程**：
```
用户点击宠物 → 弹出轻量互动面板 [🍖][🎾][💗]
  ↓ 选择食物
宠物进入 EAT 状态 → 吃东西动画（2-3秒）
  ↓
Hunger 下降 + Happiness 上升 + Affection 微增
```

### 玩耍系统

- 第一版：点击宠物 → 宠物追触摸点（简单但有效）
- 后续：逗猫棒（猫）、接球（狗）

## 七、健康助手联动

宠物 = 健康助手的"情绪化人格出口"。

| 健康事件 | 宠物反应 |
|----------|----------|
| 久坐提醒触发 | 宠物站起来、伸懒腰、看向用户（替代冷冰冰的弹窗） |
| 用户起立 | 宠物开心、摇尾巴、Affection+1 |
| 用户喝水 | 宠物开心、Happiness+3、气泡"好喝！" |
| 喝水目标达成 | 宠物 CELEBRATE 状态、跳跃 |
| 健康目标全部达成 | 宠物大庆祝、特殊动画 |

**关键设计**：宠物不代替健康提醒，而是让提醒变得有温度。

## 八、锁屏常驻机制

```
standby_overlay (全屏)
├── 状态栏（时钟+天气+WiFi/BT）—— 不动
├── 双圈（喝水/久坐）—— 不动
├── AI 语音圈 —— 不动
├── 音乐控件 —— 不动
├── 健康卡（底部）—— 不动
└── 宠物精灵（可移动区域）—— dm_pet 管理
```

- 宠物在自己的区域内随机移动（不覆盖其他 UI 元素）
- 宠物可触摸，点击后弹出轻量互动面板
- 退出 standby 时：宠物暂停动画（节省 CPU）
- 再次进入 standby：恢复，不重复创建

## 九、持久化

### JSON 结构（/data/pet_state.json）

```json
{
  "version": 1,
  "pet_type": "cat",
  "pet_name": "小咪",
  "hunger": 45,
  "energy": 72,
  "happiness": 68,
  "affection": 35,
  "health": 95,
  "growth": 127,
  "last_interaction": 1694000000,
  "last_update": 1694000000,
  "created_at": 1693500000,
  "total_days": 6
}
```

### 保存策略
- 每60秒自动保存
- 关键事件（投喂/成长/目标达成）立即保存
- 进程退出时保存

### 离线时间计算
```
elapsed = now - last_update
hunger += elapsed_hours * hunger_rate（上限100）
energy += elapsed_hours * energy_rate（上限100，离线时缓慢恢复）
happiness -= elapsed_hours * 0.1（下限30）
```

## 十、性能约束

| 约束 | 值 |
|------|------|
| LVGL 对象总数 | ≤ 15（宠物相关） |
| 精灵图尺寸 | 120x120 或 160x160 |
| 动画帧率 | 2-4 FPS（不是60FPS游戏） |
| 事件轮询 | 100ms timer（10Hz） |
| 动画帧切换 | 300-500ms |
| 内存占用 | ≤ 2MB（含精灵缓存） |
| 精灵格式 | ARGB8888（与现有图标一致） |
