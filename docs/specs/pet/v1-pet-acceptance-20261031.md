## 验收结论

**完整电子宠物养成验收：不通过。** 已有动作播放器和局部触摸互动可用，养成闭环仍有程序缺陷与设计缺口。
尚缺的不仅是板测：饥饿提醒漏发/不重发、主屏计时暂停、成长奖励缺少节制、属性缺少行为反馈等必须先处理。
“图片全部生成”“局部测试通过”“固件打包通过”分别是阶段证据，不能替代产品验收。

P302 主要解决素材，P303 解决接入，P304/P305 解决局部输入与反馈；这些任务未形成完整养成计划。
旧产品规格仍是 9 月草案；其猫狗双宠、饥饿数值方向、三连击、尺寸和帧制等与当前实现冲突。
不恢复已取消的狗、不以旧草案逐条要求补回功能；需以用户当前目标重新确定 V1 单猫养成合同。

## 当前用户实际怎么使用

实际猫挂在锁屏；设置中的“宠物”子页是动作预览、资料与配置页。
该页没有实际喂食/逗猫按钮，也没有说明双击喂食或按住头部抚摸。
在预览里播放吃饭、贴贴不会改变真实宠物属性；预览不是养成入口。

## 当前数值和时间规则

内部 `hunger` 越大越饿，界面饱食度=100−hunger；后续文案统一使用饱食度。

| 项 | 当前实现 | 审计判断 |
|---|---|---|
| 新宠 | 饥饿50、精力80、快乐60、亲密20、健康100、成长0 | 有默认数据；没有首次引导 |
| 在线饥饿 | 累计60次分钟事件饥饿+1 | 从初始50到>80至少31小时有效推进；主屏会暂停，实际更慢 |
| 在线精力 | 每120次分钟事件-1；睡眠每3次+1，进入睡眠额外+5 | UI可见性影响时间；睡觉也累计精力衰减 |
| 在线快乐 | 实际每200次分钟事件-3 | 与代码注释“每10小时-3”冲突，10小时实际-9 |
| 在线健康 | 饥饿>80累计60次分钟事件-1，最低30 | 健康数值没有进一步影响动作或恢复途径 |
| 亲密 | 抚摸/喂食/玩耍累加并封顶100 | 未用于回应强弱、偏好、主动亲近 |
| 成长 | 按交互次数累加，500成年 | 缺少有效互动判定、奖励间隔和阶段反馈 |
| 陪伴天数 | 只在加载存档时加离线整天 | 连续开机不累计；多次短离线不累计完整陪伴天数 |
| 离线 | 仅0<离线整小时<720时结算 | ≥30天直接跳过，未按30天封顶；线上/离线快乐速率不同 |
| 保存 | 60秒、投喂、设置等保存，tmp+fsync+rename | 小数分钟累计不持久化；文件错误返回未闭环；断电与坏档恢复未完整验 |

## 已确认问题及优先级

优先级是本次验收建议：P1阻止完整养成交付，P2为边界一致性问题。
设计缺口和代码缺陷分列，不把未确定的奖励数值伪装成已违反的需求。

### P1 程序缺陷：饥饿提醒生命周期不完整

- `pet_core_enter_initial()`只选饥饿动作，不调用提醒回调。
  宿主复现：开机饥饿90，状态HUNGRY，10次分钟检查后提醒请求仍为0。
- 正常转入HUNGRY会请求一次；红泡8秒后消失，而同态动作重选不再请求。
  加速引擎5分钟仍饥饿，累计提醒请求仍为1；“core再次触发”的注释与实现不符。
- 挂起/回锁屏、关闭再打开提醒、夜间/吃饭打断后是否补提醒，没有统一补发策略。
- 初次创建和持续同态两条已有复现；其余入口应加入修复回归，不能先报通过。

### P1 程序/产品缺口：时间推进依赖锁屏可见性

- `dm_pet.c:119`的`timers_pause(true)`同时暂停动画、行为和属性timer，主屏仅save/poll继续。
- LVGL宿主复现了该timer状态；返回锁屏仅resume，无按离开时长结算。
- 用户打开宠物页查看状态时，真实宠物的属性推进也已停止。重启后才可能按旧时间戳补离线量。
- 程序是否在线、猫是否可见，不应隐式决定养成时间。应独立结算经过时间，暂停可见动画即可。

### P1 功能缺失：用户期望的“饿了喵喵叫”没有实现

- core/view/facade/宠物页没有猫叫或呼噜音频调用，只有文字和动画；未发现可验收的宠物音效入口。
- 尚无饥饿叫声的重复间隔、静音/夜间策略、与音乐和语音的优先级规则。
- 不允许把“呼噜呼噜~”标签写成已实现呼噜声，也不允许以音箱能播音乐证明猫叫已实现。

### P1 产品缺口：成长和六属性未形成反馈闭环

- 真实引擎输入500次点头，每次间隔900ms，450秒到成年、亲密100；没有奖励限频。
  此实验绕过LVGL手势，只证明引擎无节制；真实触摸需稳定命中并避免800ms双击窗，速度待板测。
- 饥饿0时连续10次间隔1501ms投喂，仍成长+10、亲密+20；未区分饱腹拒绝与有效进食。
- 逗猫奖励看进入模式时长，不看是否追过手指；有效玩耍判定缺失。
- 阶段只有名称/零食门槛，亲密和健康没有相应行为差异，快乐主要只在<20时切状态。
- 奖励间隔和阶段差异尚未定稿；这些是养成方案不足，不通过加几条动画就能闭环。

### P1 产品缺口：养成入口不完整、手势难发现

- “宠物”页没有真实照顾入口；用户需要离开该页进入锁屏，再猜到双击猫。
- 缺少喂食/抚摸说明、当前需求、下阶段目标、拒绝原因的完整呈现。
- 5秒关闭菜单是否足够，600ms前8px移动是否误判拖动，均需真实触屏验收。

### P2 已复现：数值、重养、离线与存档边界

- 10小时在线快乐60→51，与注释目标57不一致；下限也与旧规格冲突。
- 累计59分钟后重养，1分钟新宠饥饿50→51：函数内static累计器没有清零。
- 离线31天重新加载，饥饿/精力/快乐/天数均未结算；所谓“最多30天”实际是跳过。
- 名字含换行时保存出不合标准JSON的文件；本仓cJSON宽松解析仍能读回，**未复现丢档**。
  首轮审计测试错误预期“读坏档回默认”而失败，已校正实验，只报告标准JSON非法。
  普通单行键盘是否可输入该字符未验证；API/语音输入须约束或正确转义。
- 保存失败、存储满、掉电窗口、时钟倒退、跨日/连续开机天数的覆盖仍不足。

## 补齐方案草案：先确定行为，再实施和验收

以下是可审阅方案，不是已完成清单。保留单猫、现有素材与架构，先处理功能合同，不要求继续铺图。

| 顺序 | 工作包 | 具体结果 | 放行证据 |
|---|---|---|---|
| 1 | 固定用户入口 | 宠物页可发现喂食/玩耍/抚摸方法和真实状态；锁屏保留快捷交互；预览与真实互动清楚区分 | 新用户能按页面说明独立完成喂/摸/玩，真实存档同一份 |
| 2 | 时间与属性 | 统一高饥饿方向、在线/离线同源结算、上限/下限、跨日、重养累计清零 | 1min/1h/24h/31d、主屏/锁屏/重启结果一致，时钟倒退不刷收益 |
| 3 | 需求与提醒 | 阈值进入、启动恢复、重入锁屏、持续饥饿、提醒关闭/重开、忙碌推迟均有确定行为 | 一次需求状态可跨页面/重启恢复，提醒有冷却且可被有效喂食解除 |
| 4 | 喂食闭环 | 可见入口→选择→接受/拒绝→动画→数值→饱食反馈→保存；不因无效投喂奖励成长 | 普通、满腹、冷却、未成年零食、睡眠/语音/玩耍冲突均有可见结果 |
| 5 | 抚摸/玩耍闭环 | 轻点头、身体、长按、滑动有明确反馈；玩耍按有效参与计奖励 | 一次有效互动只奖一次，取消/离开/超时不残留，空挂模式不奖 |
| 6 | 成长与关系 | 成长进度可解释，阶段有行为区别，亲密影响回应；健康/心情有可观察影响与恢复 | 阶段边界99/100/499/500通过，连续快速输入不把养成变成刷次数 |
| 7 | 声音 | 接入猫叫/呼噜与事件对应；遵循提醒、夜间、音量和语音忙碌策略 | 板端可听见正确音效，静音/夜间不扰民，停止/切页无残音 |
| 8 | 存档与恢复 | 名字合法编码、写错反馈、旧档迁移、坏档安全恢复、关键事件持久化 | 重启不丢已确认互动；坏档/满盘/掉电有明确退路，不覆盖用户原档做实验 |
| 9 | 板端验收 | 同次构建源码/资源/镜像身份绑定，真实触屏与声音逐项走查 | 以下验收矩阵全闭环；板测未做不能签整体验收 |

产品取舍必须在实施对应项前确定：喂养周期、满腹是否拒绝、奖励间隔/阶段意义、提醒间隔/声音策略。
建议初始合同如下，供用户调整，**未把这些数字写入固件**：

- 饱食度≤20进入饥饿需求；喂鱼后升至≥40解除，使用滞回避免反复进出。固定一天喂几次后再反推衰减。
- 可见且白天时首次提示8秒；仍饿至少30分钟后才再提示；忙碌推迟到动作结束；重新可见时检查到期提醒。
- 饥饿猫叫随有效提醒一次，不循环播放；夜间22–06和静音只保留安静表现；语音忙碌时延后，不能打断语音。
- 满腹不再增成长；摸头轻点即时回应、持续抚摸≥1秒才算有效养成；同类奖励至少间隔30秒。
- 玩耍需至少3秒真实追手/扑跳才计奖励；阶段0/100/500可先保留，但增加明确进度和不同回应倾向。
- 不引入死亡或强制签到；健康低通过照顾恢复，所有展示属性必须有行为作用及可恢复路径。
