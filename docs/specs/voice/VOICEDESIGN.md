# VOICEDESIGN.md — 声音交互系统（Voice Director）设计+实施总指导

> **定位**：AGENTS.md 的**下级文档**（上级=AGENTS.md，同级参考=devlog.md）。
> **读取时机**：凡涉及 语音/声音/提示音/编排/播放策略 的需求，先读本文件进度表，再决定从哪个 Phase 继续。
> **背景**：用户提供 `voicedesight.txt`（ChatGPT 声音交互分析，5 项交付物要求）。第一阶段**只设计不写代码**。

## 一、目标与产品原则

- 从「坐下 → 播固定 WAV」升级为「**人体感知 → 上下文 → 是否说话 → 说什么 → 播放哪个 WAV → UI 联动 → 下一次行为**」完整系统
- 核心：**知道什么时候闭嘴，与知道什么时候开口同样重要**
- 人设：**凡人修仙传「银月」**——说话好听、可爱、灵动、**贱兮兮**（俏皮调侃）。桌边偶尔插嘴的灵动损友，不是智能音箱、不是定时播报器；称呼保留"主人"（用户已拍板）
- 台词风格迁移：现有 cfg/UI 毒舌"牛马"文案在 Phase 1 重写为**银月语感**（灵动俏皮为主、调侃为辅、关心时温柔、安静时闭嘴）；保留"搬砖/工位"等现代调侃语境，不搞修仙词汇堆砌
- 不破坏现有音频链路：`dm_tone_play` / `dm_tone_worker` / 音频仲裁 / PTT 打断 全部保持

## 四、硬约束（写死，实施时逐条对照）

1. **不改音频播放链路**：dm_tone_play/dm_tone_worker/仲裁层/PTT 打断 保持现状；Director 只做决策层
2. **wav 格式**：1ch 24kHz 16bit PCM（合成脚本 tts_proto 已有工作流，PC 端执行）
3. **不批量生成 WAV**：先定"何时说/为何说/说什么/何时闭嘴"，第一批 ≤30 个
4. **阈值全部可配**：离开时长/次数/冷却时间走 `/data/dm_health.cfg`，不写死
5. **资源体积**：先查 res 分区容量（sys_partition.fex）再定第一批规模
6. **现有 12 个 wav 不删除**：降级为资源库的一部分（Voice Director 的选择池），逐个在资产规划里给处理建议
7. **静默也是输出**：决策结果含 VOICE_NONE / VOICE_UI_ONLY（静默但 UI 提示），不算失败分支

## 五、决策引擎设计要点（Phase 3 展开，先记方向）

```text
Context(坐下事件+历史) → Should I speak? → Personality(时段/情绪曲线)
→ Category(回来/吐槽/关心/粒子/提醒) → Weighted Random(排除最近播放+cooldown+权重调整)
→ WAV 选择 → Audio(dm_tone_play) + UI 联动 → Interaction Log(更新历史)
```

- 选择流程：候选池 → 剔除 recent_played → 剔除 cooldown 中 → 剔除不匹配人格 → 权重计算（吐槽过多→caring/silent 权重↑）→ 加权随机
- 一天情绪曲线：早晨轻松 → 上午正常 → 中午关心吃饭 → 下午轻微吐槽 → 晚上关心 → 深夜温柔/少说话
- 数据来源：用户姓名(USER.md=主人)/时间/天气(/data/dm_weather.state)/喝水次数/连续坐姿/今日提醒次数/最近离开时长/最近 AI 对话/音乐状态
