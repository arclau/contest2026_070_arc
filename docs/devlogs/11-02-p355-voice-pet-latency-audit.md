# P355 V1 对话延迟与宠物停帧核验

目标：确认用户反馈的 AI 对话慢、宠物动画卡顿，并只对有证据的层做优化。
平台：V1 ynm3000 实机串口；本轮只读测量，未刷诊断固件。

## 证据

- 采集：`logs/serial/20261102-045200_p351-0452.log`，取最后一次 BOOT #4 之后，
  至 05:56:55 UTC；汇总 `output/p355-latency-pet/baseline.json`。
- 对话：8 次 ASR 耗时 896～1548ms，中位 997ms；只有 1 次完整模型+播报时间线。
  该轮松手→首个音频写入 3692ms：ASR 1066ms、ASR 后至 TTS 起播 1631ms、
  TTS 起播至首写入 995ms；整个播报结束于 7678ms，xrun=1，short=0。
  另一轮 LLM 流式完成于 +6172ms，但没有完整音频终点；不能代表典型首音。
- 宠物：15 个 `[perf] 60s` 窗口刷新中位 20ms、p95 中位 31ms，最坏单轮 111ms；
  没有 P348 那种持续 1.3s 壁纸解码（`decode_png`=0）。`drop` 是采样溢出，非掉帧。
- 同段有 1442 条 `missing frame`、471 次 `PNG input mismatch`，涉及 57 个 asset。
  同一资源的多次读取 CRC 会变化，前帧复用使宠物看起来停住。Wi-Fi 固件下载也有一次 0x27。

## 判断和补丁去留

O：宠物停帧可确认；UI 整体长时间冻结的证据不足。
H1：底层 NAND/romfs 读路径偶发返回坏字节。H2：G2D DMA 与读取并发干扰。
本轮数据能支持“取帧失败造成视觉停顿”，不能区分 H1/H2，根因仍未知。
未修改应用素材缓存、重试、校验或日志；AGENTS §五禁止再给读路径叠应用层补丁。

对话首音 3.69s 的分段中，ASR、LLM、TTS 均在云端；现有 P342 首句流式已生效。
本次只有 1 个完整回合，尚不能把单次数字升级为稳定分布，也没有证据支持盲目改模型参数。
因此本轮没有保留代码补丁；没有伪称“延迟已优化”。

## 下一次区分实验

在相同固件/素材下只改变 G2D 旋转是否参与显示，分别记录固定时长内
`PNG input mismatch` 和帧请求次数，并核对刷入固件身份。
若失败率随 G2D 开关显著变化，转查 DMA/缓存一致性；若不变，转查 NAND/romfs 读与 ECC。
该实验需诊断固件和板端运行，当前未执行；不能把假设写成根因。
