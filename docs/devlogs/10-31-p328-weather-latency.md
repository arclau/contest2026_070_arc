# P328 — V1 天气显示慢：计时与更新节奏

2026-10-31；V1 `ynm3000`。用户反馈天气 API 慢，希望更换。
验收目标：联网后天气卡及时显示有效的当前值及五日预报，
串口耗时可用于比较服务；板端视觉及实际耗时待验。

## 现象与判断边界

- 当前服务是 Open-Meteo。10-31 23:38 烧录后自动启动时，天气在 Wi-Fi 未就绪时报 DNS 失败；
  Wi-Fi 于 23:39:06.675 联网，天气于 23:39:23.436 报成功。
- 旧日志中首个成功请求耗时出现负数或数百万毫秒。`dm_weather_fetch()`
  使用 `gettimeofday()` 计算耗时，而同一函数会从 HTTP Date 调用 `settimeofday()`；
  因此该耗时失真，不能据此给 API 排名。
- `clock_update_cb()` 已在 Wi-Fi 获得 IP 的边沿踢请求；
  `weather_update_cb()` 原来仍每 30 秒才查看一次后台结果，开机失败后还会再等 30 秒显示。
- 和风天气官方接口需要专属域名、凭据和 HTTPS；当前客户端仅为明文 HTTP socket。
  本轮没有可用的新服务配置，因此尚未更换服务。

## 最小改动

1. `dm_weather.c`：请求耗时改用 `CLOCK_MONOTONIC`，避免 HTTP Date 对时影响测量。
2. `ui/ui_home.c`：取数期间每秒检查结果；首次失败且未联网时等待 Wi-Fi，
   已联网失败按 5 秒间隔重试；成功后保留原两小时周期。
