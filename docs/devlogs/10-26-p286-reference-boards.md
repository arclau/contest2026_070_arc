# P286 参考板对照 — 两台能工作的 HX83102B

> **2026-10-27 接线更正**：用户确认当前 INT 没有电平转换，仅 10 kΩ 上拉到 1.8 V；
> RST/SDA/SCL 才有转换。下文“全部信号板端 3.3 V”不可用于当前 INT，
> 电气原因不能整体排除。见[专项复核](10-27-p286-touch-review.md)。

目标：把"同型号模组、能正常触摸+显示"的实测事实固定下来，作为 R528 V2 触摸排障的对照基线。
平台：外部参考板（只读采集，未改其任何配置）。验收：事实可复核，假设与事实分开。
本文只记录参照板；R528 侧实验仍在 [P286 触摸驱动移植](10-25-p286-touch-driver-port.md)。

> 采集方式：局域网 SSH 只读。**地址、账号、口令不入档**，需要复采时向用户索取。

## 参考板 A：ROC-RK3588S-PC（2026-10-26 采集）

| 项 | 实测值 | 来源 |
|---|---|---|
| 模组 | BOE/HX83102B，与 V2 板同型号 | `/proc/device-tree/model` |
| 系统 | Linux 6.1.118 aarch64 | `uname -a` |
| 触摸驱动 | 内置，dmesg 前缀 `[HXTP]`；I²C 设备名 `hxcommon`；input 名 `himax-touchscreen` | dmesg / sysfs |
| I²C 控制器 | `i2c@feac0000`（i2c-4），引脚 gpio1-2/1-3（`i2c4m3-xfer`） | pinctrl debugfs |
| **I²C 速率** | **400000 Hz**（DT `clock-frequency`） | `od` device-tree |
| 地址 | 0x48 | DT `reg` |
| **电平转换** | **无**，转接板直连 | 用户现场 + DT 无相关节点 |
| **信号电平** | 用户万用表实测**全部 ≥2.4 V** | 用户测量 |
| 引脚内部上下拉 | SDA/SCL/RST/INT **bias disabled** | `pinconf-pins` |
| 驱动强度 | 8 mA | `pinconf-pins` |
| RST | gpio1-1（gpio-33）`out hi`，运行期常高；**仅初始化时脉冲一次** | `/sys/kernel/debug/gpio` + dmesg |
| INT | gpio1-7（gpio-39）`in hi`，**低有效、下降沿**，IRQ 79 | gpio debugfs / `/proc/interrupts` |
| 面板 | 720×1440（panel-coords = display-coords = 0..720 × 0..1440） | DT |
| 协议 | **Type B**，`touch_info_size=56`，MAX_PT=10，RX=36 TX=22 | dmesg |
| 芯片 ID | `00 2b 10 83` | dmesg/驱动 |
| 固件版本 | `0xA3 0x3A` / `0x9D 0xDC`（resident firmware，未上传） | dmesg |

初始化时序（dmesg 时间戳）：`3.139 hx83102_chip_init` → `3.152 himax_mcu_ic_reset` +
`himax_mcu_pin_reset` → `3.239 read_FW_ver`（约 87 ms）→ `3.507 touch_information` →
`3.606 input registered` → `3.606 INT falling edge, irq at gpio 79`。

运行期：IRQ 79 在 13 分钟空闲中仅 7 次，即 INT 空闲为稳定高电平，不是靠轮询读事件栈。

## 与 R528 V2 的对照

| 项 | 参考板 A（能工作） | R528 V2（E18 前） |
|---|---|---|
| 总线速率 | 400 kHz | 50 kHz（E17 试过 25 kHz） |
| 电平转换 | 无 | 2SK3018（RST/SDA/SCL） |
| 主控侧电平 | ≥2.4 V | 1.7 V（E6/E8 实测） |
| 内部上下拉 | 全部关闭 | PB2/PB3 上拉，PB4/PB5 关闭 |
| INT 空闲 | 高（可读） | 读 0 |
| RST | 常高 + 初始化一次脉冲 | 常高，E14 起失败时补脉冲 |
| 结果 | 触摸+显示均正常 | I²C 事务失败，无 /dev/input0 |

## 事实与假设（分级，未升级为根因）

- **O1（事实）**：400 kHz 在本模组上可用，参考板长期运行如此。旧"400k 不可用"只代表
  我们当时的接线条件，E18 复测方向成立。
- **O2（事实）**：参考板主控侧 ≥2.4 V、无电平转换、无内部上拉即可工作；模组不是"必须
  1.8 V 才能通"。
- **H1（待验）**：R528 的 PB2/PB3/PB4/PB5 属 3.3 V 域，保证高电平门槛约 0.7×3.3≈2.31 V；
  我们主控侧 1.7 V 低于该门槛，可能读不到模组的应答高电平。可解释 INT 恒 0、ID 位翻转、
  读中途 `st=00 lcr=2a`，但**尚无波形，不能定为根因**。
- **H2（待验）**：参考板的 2.4 V 是"外部上拉到 3.3 V → 模组 ESD 钳位"的结果，与 F101
  devlog 57 记录的"体二极管抬到 2.3~2.5 V"同型；我们的 2SK3018 把主控侧钳在 1.8 V 域，
  方向与参考板相反。
- **H3（待验）**：E2 的 RST 推挽 3.3 V（实测 2.88 V）出横纹，参考板 RST 常高 2.4 V 无横纹；
  弱上拉可能同时满足"触摸可用"与"无横纹"，但两块板面板不同（720×1440 vs 1440×720），
  不能直接外推。

## 建议的单变量实验（尚未执行）

1. 拆除 RST/SDA/SCL 的 2SK3018，改直连 + 2.2~4.7 kΩ 上拉到 3.3 V（R528 侧），关闭内部上拉
   ——复刻参考板 A 的拓扑。
2. RST 用 4.7 kΩ 上拉到 3.3 V（弱驱动，由模组钳位），不使用推挽 3.3 V。
3. INT 同样加上拉到 3.3 V，使 R528 能读到高电平。
4. 硬件改完再刷 E18（400k）对照。

预期：回到 E2 的"可触摸"。若横纹仍在，则横纹归 P285 显示线，与触摸解耦判定。

## 采集限制

- 用户态 `i2ctransfer` 访问 0x48 返回 **EBUSY**（内核驱动占用地址），未做总线压测；
  "参考板能承受多快的连续读"仍未知，需先解绑驱动。
- 2.4 V 为用户万用表读数，无波形、无测点照片；软件侧只能读到 `bias disabled / 8 mA / out hi`。
- 参考板面板为 720×1440 竖屏，与 V2 的 1440×720 不同，显示结论不可直接搬用。

## 参考板 B：F101 / Yuzuki Neko（2026-10-26 冷启动实测）

采集方式：主机 `/dev/ttyUSB0` @115200 8N1，F101 UART1（PB0/PB1）。冷启动完整捕获。
日志：`logs/serial/20261026-092348_f101.log`（含开机前段少量二进制噪声，读时用 `tr -d '\0'`）。

启动链：SyterKit v0.5.0（RISC-V C907）→ Zephyr（build `84146a9e508c`）→ NekoBox。
显示：`720x1440 @ 60 Hz`，软件旋转 90° 后界面 `1440x720`。

### 触摸初始化原文（uptime 1.501 s）

```
[00:00:01.501] <inf> himax_hx83102: probe=1 speed=100000 try=1 SLA+W=0 t=176us RST=0 INT=1
[00:00:01.504] <inf> himax_hx83102: ID=00 2b 10 83
[00:00:01.504] <inf> himax_hx83102: AB identified; observing resident firmware, no upload; polling 20 ms
```

即：**100 kHz、第一次地址探测就 ACK、176 µs 完成、第一次读 ID 即正确**。

### 该构建的驱动参数（`overlays/boe-hx83102b-touch-intgate.conf`）

| 参数 | 值 | 说明 |
|---|---|---|
| 速率阶梯 | 100 k → 50 k → 25 k | 每档 `PROBE_TRIES=3`，失败才降档；记住上次可用档 |
| `POLL_MS` | 20 | INT 拉低时的事件读周期 |
| `IDLE_MS` | 200 | INT 为高时最多每 200 ms 读一次 |
| `ERR_LIMIT` | 5 | 连续失败 5 次才重新识别 |
| `RESET_ON_INIT` | **未开** | 驱动**从不配置、不驱动** RST（PD3 与面板复位共用，脉冲会出横纹） |
| INT | PD2，低有效，下降沿 | 运行期空闲为**高** |

### 证据边界

- `RST=0` 是 `gpio_pin_get_raw()` 的读值，而该引脚因 `RESET_ON_INIT=n` **从未被驱动或配置**，
  不能当作"模组 RST 实际为低"的电气结论。
- 本次日志未出现 `gap test read1`，虽然该 conf 写了 `GAP_TEST=y`；说明板上镜像与当前源码树
  不完全一致，参数只能代表"这一版镜像"。
- 本次没有触摸动作，未采到报点帧。

### 用户更正（2026-10-26，关键前提）

**F101 与 R528 共用同一块屏幕、同一块转接板，上拉电阻与电平转换电路完全相同。**

因此"参考板没有把主控侧压到 1.7 V"这一推断作废——两台的转接板侧条件一致，
差异只能在**主控侧**（IO 域电压/输入门限、引脚上下拉、TWI 控制器）。此前基于
"F101 用 2SK3018 到 1.8 V、RK3588 直连 2.4 V"得出的电气差异解释不再成立。

### 三台机器的事实（修正版）

| 项 | RK3588（不同转接板） | F101（**同一块**转接板） | R528 V2（同一块） |
|---|---|---|---|
| 速率 | 400 kHz | 100 kHz | 50 kHz（25/100/400k 均试过） |
| 转接板 | 直连 | 2SK3018 + 上拉 | **完全相同** |
| 主控侧电平 | ≥2.4 V | 未测（**待测**） | 1.7 V |
| RST | 常高 + 初始化脉冲 | 驱动不碰 | 常高 + 失败脉冲 |
| INT | 空闲高 | 空闲高 | 读 0 |
| 首次探测 | 正常 | 1 次 ACK | 从未一次成功 |
| 结果 | 触摸+显示正常 | 触摸+显示正常 | 无 /dev/input0 |

### 电压实测（2026-10-26，用户万用表，两板同测点）

| 信号 | F101 板端 | F101 屏端 | R528 板端 | R528 屏端 |
|---|---|---|---|---|
| SDA / SCL / RST / INT | **3.3 V** | **1.7 V** | **3.3 V** | **1.7 V** |

**两台的静态电平完全相同，转接板、上拉、电平转换、两侧电压都一致。**
H4（主控输入门限）与 H5（高压侧供电缺失）同时被否定，电气差异不再是候选解释。
INT 内部上拉在 R528 侧确为关闭（E5 起 `GPIO_PULL_DOWN_DISABLED`），但板端有外部
3.3 V 上拉，关闭内部上拉是正确的，不构成差异。

### 剩下的差异只在主控侧

F101 驱动的初始化序列（`input_himax_hx83102.c` 的 `bridge()` + `read_id()`）与本项目 E13
**逐笔相同**：读 0x08 → 写 0x13=0x31 → 写 0x0d=0x10 → 读回 0x13 → 读回 0x0d →
写 AHB 地址 5 字节 → 写 0x0c=0 → 读 0x08 四字节，共 **8 笔，笔间无延时**，100 kHz。
它一次通过。所以"背靠背事务本身"不是必要条件，"加间隔"也不是解法。

同一块 R528 板、同一速率下的对照（E12，2026-10-26 05:45–05:47）：

- 控制台 `i2c dev -b 0 -f 50000` 探测 **ACK**，复探 5/5；
- 控制台 `i2c dump -b 0 -f 50000 -a 48 -r 30 56` 读到**合法空闲帧** `55×ff+0x37`；
- 同一时刻、同一速率下，驱动 init 每轮 6 笔背靠背全部 `transfer=-1`。

把三条并起来：电气相同、序列相同、速率更低，仍然只有 R528 的**连续事务**失败，
而同一控制器的**单笔事务**成功。差异收敛到 R528 TWI 控制器/驱动在**相邻事务之间**
的行为（STOP 完成与下一笔 START 的时序、总线空闲判定），不是电平、不是 IC、不是节奏本身。

支持材料：E13 的 `[TWI0-E13]` 在长读中途报 `st=00`（总线错误）与 `lcr=2a`
（SCL 高、SDA 被拉低），E14 用 9 clock + STOP 能反复救回总线——说明总线确实会在事务
边界卡住，而不是 IC 不应答。

### E19 提案（已修订，未实施）

单变量：**每笔传输前等待总线空闲（SDA=SCL=1，超时 10 ms），传输后确认 STOP 完成**；
其余保持 E15（50 kHz 可改为 100 kHz 作为第二个变量单独做）。

- 若 init 通过并读到 `00 2b 10 83` → 根因方向为"事务边界总线未空闲"，修法是把等待
  做进 `r528_transfer()`，而不是加延时；
- 若仍失败 → 转 GPIO bit-bang 复刻同样 8 笔，彻底切开 TWI 外设与线路。
