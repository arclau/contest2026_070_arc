## 四、本轮技术结论（值得记住的）

**P348：`drop` 不是丢帧。** 它是 `dm_perf.c` 里 `PERF_SAMPLE_MAX=1024` 的采样数组溢出计数，
实测 `flush=1350 → drop=326`，正好 1350-1024。已更正 P346 文档。

**P351：语音命令会被"自己那句回话"打掉。** 说「睡觉」→ 助手回「好，我去睡了」→
TTS 起播发 `PET_EVT_VOICE_PHASE(3)` → `pet_request_action(SPEAK)` 撞上过渡分支
（当前动作是 `SLEEP_ENTER`）→ 先播 WAKE → `animation_done` 把 `g_state` 写回 IDLE。
**任何"语音强制某个状态"的功能都要检查这条路径**，因为播报阶段一定会来打一次。

**P352：本地命令不本地。** `g_local_cmd_matchers[]` 只是跳过 LLM，输入仍是云端 ASR 文本。
断网时所有语音指令（含宠物指令）都不可用，这是架构决定的，不是 bug。

**巡检结论（P350 附带）：** 素材 82/82/82/82/82 一致；`pet_png_crc.h` ↔ 磁盘 ↔ `res.fex`
82 条全对；11 个宠物状态全可达且都有行为映射；9 个"`CFG_*` 没读"的键其实走
`AGENT_CFG_KEY_*` 宏。**没发现新的同类 bug。**

死代码（不影响行为）：`s_wake_triggered`（只写不读）、`g_last_tap_ms`（从未使用）、
`g_tap_count`（9 赋值 0 读取，但 `pet_view.c:814` 注释还写着"双击/三连点直开喂食"）。

## 六、工具/环境坑（这次踩到的）

1. **串口抓取会失锁**：刷机时 USB 串口重枚举，旧 `dm_serial_log.py _daemon` 的 termios
   掉回默认波特率，表现为**低速乱码**（~89 B/s、零可读行、无 `[`/`nsh`）。
   很容易误判成"设备没起来"。判据：设备能进桌面但串口全乱 → 重启抓取进程即可。
2. **日志行会自动换行**，关键词可能被截断在两行之间，`grep 'voice_evt('` 会漏计。
   要么 `tr -d '\r\n'` 后统计，要么用短词。
3. **`stat -c %s` 对 `latest.log` 符号链接返回的是链接长度（36）**，要 `stat -Lc %s`。
4. **构建脚本用 `@` 抑制了逐文件编译行**，日志里只有 `CPP:`/`LD:`。
   判断"是否真的重编"要看 `vendor/.../<name>.c.data.dm.*.o` 的 mtime，不能 grep `CC:`。
5. **改头文件后必须 touch 所有 include 它的 .c**（增量构建不跟踪头文件依赖）。
