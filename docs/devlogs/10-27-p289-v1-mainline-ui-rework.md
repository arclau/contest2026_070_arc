## 4. 关于“V2 更流畅”的判断

用户观察：V2 UI 流畅。核对后能确认的与不能确认的分开写：

**已确认相同**：两块板 LVGL 配置逐项一致——`LV_DEF_REFR_PERIOD=16`、32 位色、`LV_USE_DRAW_G2D=y`、`LV_DRAW_SW_ASM_NEON=y`、FreeType 缓存 1024。所以流畅度差异**不来自 LVGL 配置**。

**已确认不同**：

1. 像素量 2.2 倍（1920×1200 vs 1440×720），这是硬差距，架构改不掉。
2. V2 有 `dm_theme` 统一材质/分辨率入口；V1 没有，`lv_obj_set_style_*` 在 1.5 万行里散落（text_color 209、font 201、bg_opa 186、bg_color 172、border_width 160、radius 141）。

**未知**：V1 当前实际帧时间没有基线数据，V2 的流畅也没有量化。**不能把“改造架构”直接写成“会更流畅”**；架构改造的确定收益是可维护性与一致性，帧率收益待测。

## 5. UI 改造范围（2026-10-27 用户确认）

目标：**换结构与技术，不改外观与布局**。验收必须包含改造前后逐页截图逐像素一致。

| 面 | 现状 | 改造 | 视觉影响 |
|---|---|---|---|
| 样式系统 | 仅 1 个共享 `lv_style_t`；约 1500 处内联 `lv_obj_set_style_*`（text_color 209 / font 201 / bg_opa 186 / bg_color 172 / border_width 160 / radius 141） | 抽 5~8 组共享 style（card/text/row/button/icon），对象 `add_style` | 零 |
| 页面生命周期 | `close_subpage` 销毁整页 + 14 个手写 cleanup；重进全部重建 | 页面注册表 + 缓存（hide/show），统一 create/cleanup 接口 | 零 |
| 刷新纪律 | 每秒 set_text、重复 set_style、全屏 invalidate | 静态文本、只 invalidate 变更区域、去掉重复写 | 零 |
| 模块边界 | `deskmate_ui.c` 3708 行仍含音乐核心/AI 页/构建器 | 拆出编译单元，不改行为 | 零 |

**不在范围**：材质配方（颜色/渐变/阴影值）、布局坐标、控件层级。P271 的玻璃配方会改观感，不作为目标；只借鉴其“单一原语、去重复副本”的结构结论。

**度量门槛**：改造前先记录每页首帧耗时、导航耗时、静态帧时间、堆占用；改造后逐项对比。结构改造主要改善导航延迟、内存与首帧，**不保证静态帧率上升**——绘制量与外观强相关。

## 6. 约束

1. **V1 已有模拟器**（[P290](10-27-p290-v1-sim-hookup.md)，1920×1200）：UI 改造可在 goldfish 预览；硬件功能与最终效果仍需刷机验证。
2. **2.3 MP 像素预算**：V1 的帧率天花板低于 V2，动画/模糊类效果要按实测取舍。
3. **未提交改动**：`apps/luncher_dm` 有 146 个 `pet_cat_*.c` 未跟踪但被 Makefile 引用；`luncher_dm_v2`、两个 board 目录均 untracked。改造前不要 `git clean`。
4. **共享层侵入**：`chips/.../twi/hal_twi.c` 有 +405 行无 CONFIG 门控，V1 固件也带着它；V1 板测若触摸异常，先怀疑此处。
