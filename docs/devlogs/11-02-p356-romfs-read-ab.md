# P356 ROMFS 重读实验（阶段 A）

**P357 校正（11-02）**：P314 已记录板端 `cmp` 误报，且打印的 `byte 128`
可能只是比较块长。P356 的差异判定只依赖 `cmp`，故本实验不能证明
ROMFS 重读结果不同；下列数值仅保留为原始命令输出。宠物输入 CRC
与期望值不符的独立证据见 P314/P355。

目标：验证宠物停帧对应的 `/resource` 读不稳定，并准备 G2D 对照。
平台：V1 ynm3000 当前实机；串口会话 `logs/serial/20261102-045200_p351-0452.log`。

O：P355 已确认 57 个宠物素材读回 CRC 变化、猫复用旧帧。根因仍未知。
假设：H1 G2D/缓存并发干扰；H2 ROMFS/NAND 读路径自身返回坏字节；H3 tmpfs 写/比较错误。

E1 唯一变量为输入文件系统，显示保持运行。板上 NSH 命令行截断 68 字符宠物文件名，
因此改用同在 `/resource` 的 7,943,504B `fonts/MiSans-Normal.ttf`，不改原文件。

- 复制三次至独立 `/tmp` 文件：大小均为 7,943,504B；两两 `cmp` 都在第 128 字节不同。
- 从同一 `/tmp` 副本各复制 2KB，两份 `cmp` 一致：tmpfs 重读在此样本未复现。
- 从原 `/resource` 文件各读 2KB、4KB，两次各自一致；各读 64KB 两次则从第 128 字节不同。
- 64KB 副本的前 4KB 与单独 4KB 读取有一份一致；失效随请求规模/时序变化。
- 原资源及所有临时副本未改；本轮 `/tmp/p356a`～`/tmp/p356l` 已清理，首尾确认不存在。

C（已撤回）：原结论称较大 ROMFS 读取结果不稳定，但历史 P314 证明
`cmp` 在本板会误报，现不能从本实验判断复制结果是否真的不同。
日志串口输出可能与命令回显交织，因此仅采纳完整 `cmp`/字节数结果。
