## 1. 给接手 AI 的任务定义

请交付一个**可重复使用的 1440×720 goldfish 开发环境**，分两阶段完成：

2. **固定使用方式**：整理并实测统一操作入口、状态检查、日志与简短使用文档，证明新终端可以直接使用。

当前第一步是保存并复现基线，不是立即重构脚本。每阶段有证据后再进入下一阶段；若问题实际落在启动工具，允许先做最小工具修复以获得观测。

## 4. 工作方式：短判断、可验证、能收敛

这是工作协议，不要求暴露长篇内部思考。每次关键行动前只给可检查的判断摘要：

```text
当前目标：要让哪个现象改变？
已有证据：来自哪次构建、日志或源码？
当前假设：只选一个，尚未证明。
最小实验：只改变什么；成立/不成立各预期看到什么？
结果与下一步：实际观察支持什么；补丁保留还是撤销？
```

操作纪律：

- 同时保留至多 3 个候选假设，每轮只测试 1 个。优先测试能区分不同原因的假设，不以“改起来容易”排序。
- 原因、崩溃位置、后续异常分别记录。recursive assert 常常只是后续现场；锁函数报错不自动说明锁实现有错。
- 连续 2 个实验没有缩小范围，停止加补丁，写清实验是否真正生效、观测是否可靠、还缺什么。换观测手段或补基线，不能只是换个变量继续赌。
- 编译失败不是运行假设被证伪；未运行新 ELF 的实验无效；换了错误表现不等于接近根因。
- 无反馈时先判断进程、日志去向和时间戳，不立即增大 sleep、循环重启或全量清理。
- 用户已授权的范围内持续推进，不每一步询问。只有缺外部信息、产品取舍、破坏性操作或权限限制才说明具体阻塞。
- 工具/插件不可用就用可用的终端进程管理方式，不为一项调试任务另建复杂基础设施；不绕过权限限制。

## 5. 阶段 A：复现并修复应用运行

### A1. 固定基线与观测

P256 已提供 [只读工作区检查器](../specs/misc/workspace-check.md)：先运行 `python3 /data/dm/contest2026_070_arc/tools/workspace_check.py --target sim`，跨仓调查加 `--all-repos`。其配置/ELF 哈希用于识别现场，不能代替差异备份或证明同次构建。

读取相关函数与调用路径后，记录受影响仓 HEAD/dirty diff、有效配置、ELF 哈希、启动命令、进程、日志位置。关键仓不止四个，按开发流程核对归属。保存改动和产物后，再重启目标实例；停止前核对 PID 与输出目录。

使用当前产物重复同一启动，目标是得到可比较的首个异常。若表现不一致，记录变化点，先查运行身份/环境；不要强行继续对象二分。若 syslog 禁用妨碍观测，保存 diff 后将恢复观测作为独立实验，不同轮再改 UI。

**A1 交付**：一张基线卡、可执行复现步骤、首个异常对应的 ELF/日志。没有这三项，不能写“根因已确定”。

### A2. 按证据选择实验

下表是候选方向，**不是根因排名或必须全部尝试的清单**：

| 何时考虑 | 最小验证方向 | 结果如何分流 |
|---|---|---|
| 编译宏、结构解释、资源路径与目标不一致 | 核对实际编译命令、预处理头与有效配置 | 确认污染才修生成/包含来源；未证实不要到处加 `-D` |
| 配置身份正确，异常稳定发生在首刷附近 | 保持设备/loop/刷新时序，缩小应用对象构建范围；简单背景+已启用内置字体的短 ASCII 文本 | 最小画面也崩：查公共显示/渲染/初始化；能过：按对象组恢复，二分范围 |
| 恢复某类文字/图片后才稳定复现 | 检查资源、字体返回值、对象生命周期及必要依赖 | 做局部替换对照；不全局关闭 uikit 依赖的 FreeType |

“最小画面”实验前读完整构建函数，保留必要初始化；不能删掉被后续代码使用的对象，制造第二个空指针故障。若有直接越界报告或明确回溯，优先追直接证据，不机械做完上表。

确需检查 framebuffer 时，再核对格式、宽高、stride、映射长度和缓冲区边界；不从屏幕尺寸猜像素字节数。确需检查线程/生命周期时，再查谁创建/销毁、谁写对象、回调在哪个上下文运行。每次只深入证据指向的一层。

**A2 交付**：可重复的修复前后差异与解释，恢复实验变量后验证正常路径。不允许以吞掉错误、关闭日志/检查器、永久禁用宠物来达到“不崩”。

### A3. 单独验证显示与输入链路

guest 能持续刷新后，再验证 host 窗口、截图、VNC 和输入传递；串口可先承担排障，不要求一开始就修好所有画面通道。

- 用已知测试内容确认画面来自 guest，而不是启动窗口或宿主背景；截图非黑不算应用通过。
- 检查最终启动参数和运行日志；生成 ini 的内容变化不能独自证明参数优先级。只保留实测有效的 GPU 设置，不循环 sed 或试未经证实的 HUP 热重载。
- 确认 UI 1440×720、中文与必要资源显示、点击坐标准确、能进入一个子页并返回。
- 恢复 libuv/宠物等临时改变时逐项验证；如有证据决定更换正式实现，记录原因与等价行为，不能只是遗留 `#if 0`。

## 6. 阶段 B：让下次启动无需重新折腾

在运行路径通过后，复用/整理现有工具，形成**一个受版本管理的操作入口**。先核对脚本所在仓和可写范围；不要只把改动留在未纳入版本的 `/data/vela` 或 `/tmp`。旧入口若保留，应转发到唯一实现；路径迁移与兼容方式要写清楚。

以下是待实现的接口要求，**不是已经存在的命令**。优先沿用已有命名；若增加子命令，可采用如下语义：

| 操作 | 应有行为 |
|---|---|
| `doctor` | 只检查工具、目标配置/产物、显示与端口条件；明确缺哪项及处理方式，不擅自安装/改全局环境 |
| `build` | 调用 SDK 正规入口，统一配置与工具链；重建被模拟器占用的可写镜像前协调停机；失败不启动旧产物冒充成功 |
| `start` | 无需手工补 PATH/sed/起若干后台进程；重复调用不重复开实例；无可用产物时给明确下一步，不隐式长时间全量重编 |
| `status` | 报告本实例、产物身份、日志和访问方式；区分进程存在、系统启动、应用就绪、UI/交互验收 |
| `stop` / `restart` | 只管理本实例及其拥有的子进程；核对 PID 身份，避免误杀其他任务；停止已停止实例也应正常 |
| `logs` / 截图能力 | 清晰定位当前运行日志/最近失败；支持获取画面证据，不依赖 AI 猜临时目录 |

实现要求：

1. 依据脚本位置确定工程根，支持从其他目录调用；环境依赖由入口统一处理，不依赖上一轮终端 export。
2. 有合理且可解释的就绪等待/超时；失败返回非零并指明阶段、日志。不要用固定“sleep 25 秒 + started”代替检测。
3. 优先复用现有可靠就绪信号。没有应用级信号时明确显示“仅进程启动”，不能伪报健康；必要时增加最小、无敏感内容的观测点。
4. 配置修改在受控源或生成步骤收口；重新配置/构建后仍有效，不要求用户再次手工编辑生成文件。
5. 保存失败现场再重试，日志标识运行批次/时间/产物；控制存储增长。文档只写证据路径和脱敏摘要，不粘全日志。
6. 桌面预览进程在发起它的终端退出后仍可用，且能被统一入口停止；验证实际生命周期，不仅看 `nohup` 字样。
7. 针对这些实际故障验证脚本行为，不为参数分发写大量形式化测试；不要借此扩展成通用运维平台。

## 7. 交付验收（执行时填写，不提前打勾）

以下是本任务建议的最小验收量，不是已获得的结果；长时间稳定性/全部子页另列范围。

- [ ] 同一构建正常启动 3 次，能看到目标应用；没有 recursive assert/异常重启。
- [ ] 连续运行至少 10 分钟，界面持续更新；进入/返回一个子页累计 10 次，输入仍响应。
- [ ] 主屏中文/图标及宠物正常初始化和显示，临时禁用项有逐项处理记录；硬件桩限制已说明。
- [ ] 从新终端、非工程当前目录启动成功，无手工 export、sed、起 Xvfb/VNC 的额外步骤。
- [ ] 重复 start 不增加实例；stop/restart 不影响其他任务；启动终端退出后预览仍可用。
- [ ] 一次正常重建/重新配置后按文档重启，仍正常显示，不靠残留生成文件。
- [ ] 缺产物或依赖、资源被占用等失败条件用隔离方式验证，返回清楚错误，不误报成功；不破坏当前可用环境来造故障。
- [ ] 文档包含唯一入口的真实路径、最少启动步骤、访问/截图方法、日志位置、恢复方法与已知限制。
- [ ] 根据实际修改范围完成开发流程的验证矩阵；共享 C/内核改动补 R528 pack/check_res，板测未做单列，不与 SIM 迭代混跑。

不以“编译成功、NSH 出现、窗口非黑、进程存在”替代上述验收。不能实现的项明确写未通过/受限及原因；有具体失败证据后再决定下一步。
