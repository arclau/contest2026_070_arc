# P357 ROMFS 与桌面刷新对照中止

目标：在 V1 板上区分资源重读不稳是否随桌面刷新停止而消失。
平台：ynm3000 实机；串口 `logs/serial/20261102-045200_p351-0452.log`。

O：P356 的 `cmp` 差异曾被误认为资源重读不稳；P314 已记录 `cmp` 会误报。
宠物 PNG 输入 CRC 错误仍有独立证据，根因未知。
H：H1 显示/G2D 并发干扰读路径；H2 与显示无关的 ROMFS/NAND 读异常；
H3 停止桌面的操作本身引入系统异常。

E2 预设唯一变量是桌面是否运行；固定读取 `/resource/fonts/MiSans-Normal.ttf`
前 64KB，比较独立 `/tmp` 副本。预期停桌面后若读稳定，H1 获得支持；
若仍不稳定，H1 减弱。须确认桌面真正停止且系统健康，结果才有效。

实际结果：

- 06:47:06～16 UTC，桌面运行阶段读取三次，每次回报 65536B；
  `cmp` 对两组副本都打印 `byte 128`。因 `cmp` 已知误报，A 阶段无效。
- 06:47:41 发送 `kill 44` 停桌面。06:47:44 串口收到板端时间
  14:47:42 的 `Prefetch abort`（PC/IFAR `0x50405f1a`）及内核 panic。
  先前 `ps` 的 PID 44 是桌面；但没有健康状态或显示停止的有效确认。
- panic 输出前后曾收到一次 64KB `dd` 完成行；由于串口输出滞后且内核已异常，
  这次读取不纳入 B 阶段。随后 `cmp`、桌面重启、`ps` 只有 TX，没有 RX。
  最后设备回显时间 06:47:44.914；桌面恢复未获确认。
- 串口工具显示 `boots=5` 是 panic 中 `Current Version: NuttX` 误触发启动标记，
  当时没有真实重启证据。ADB 无设备；本机 USB 仅见串口和复合 gadget，
  未发现可用远程断电通道。
- 后续 06:51:02、06:51:17 观察到两次 U-Boot 启动输出；第二次进入系统。
  06:52 的 `ps` 显示 `luncher_dm` PID 44、`ai_agent` PID 121，串口回显恢复。
  不能从日志确定复位由人工断电还是其他原因引起。
- 恢复后开机约 50 秒且桌面运行时，`cmp` 对两份 64KB 副本仍打印
  `byte 128`，但该结果同样无效；两份临时文件已清理。
- 随后再读两份 64KB 副本，`cmp` 仍报 `byte 128`；对两副本及原 ROMFS
  文件用 `hexdump skip=64 count=192` 读取，三份输出逐字节一致，且与
  宿主资源原文件对应 192B 一致。因此至少报告的第 128 字节并未损坏。
  抽样不能证明整份 64KB 均正确。临时文件已清理。
- 再拷贝一次字体前 64KB 到 `/tmp/p357k`，用板端 `hexdump` 完整输出。
  4096 行中 4095 行（65520B）与宿主原文件逐字节一致；一行受其他串口
  日志打断，随后单独重读该行 16B，也与宿主一致。故这一次 64KB 拷贝
  全部正确，`cmp` 对该类副本的报错不能用于判断内容。临时文件已清理。

C：A/B 阶段均无效，不能判断 G2D 并发是否导致读坏。`kill` 后 panic 是时间相关性，
不能据此判定 `kill` 是根因；PC 也不能在未配对确认 ELF 前直接符号化下结论。
`cmp` 数据不能用于推断开机时长对读路径的影响。一次 64KB 拷贝正确
不否定宠物读取间歇出错。没有代码或固件改动。
panic 前临时文件位于板端 tmpfs，随重启清空。

下一步：以宠物输入 CRC 日志为依据，在不终止桌面进程的条件下定位
一次坏读的具体字节与对应块；再决定是否需要 G2D 负载对照。
