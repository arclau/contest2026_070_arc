# HX83102 Touch Driver Port - R528 / NuttX (SKELETON, P274)

Ported from the Linux Himax HX83102 driver
(Firefly_SDK/kernel-6.1/drivers/input/touchscreen/hxchipset/) to the
NuttX touch_lowerhalf framework, modeled on the in-tree gt9271 driver.

## Files
- hx83102_iic_touch.c / hx83102_iic_touch.h : the driver (poll mode).
- hx83102_firmware.c : 128 KB Himax_firmware.bin as a C array, generated by
  gen_hx83102_fw.sh (regenerate if the blob changes).
- gen_hx83102_fw.sh : regenerates hx83102_firmware.c from the blob.
- Build wiring: drivers/Kconfig, r528s3-gemini-s1/src/Makefile,
  chips/r528/r528_boot.c, deskmate/defconfig.

## Key differences vs GT9271
1. 1-byte command I2C protocol (GT9xx uses 2-byte address). See
   hx83102_iic_read_cmd / hx83102_iic_write_cmd.
2. AHB register access: 4-byte addr to cmd 0x00, direction at 0x0C,
   data at 0x08; burst via 0x13/0x0D. See hx83102_burst_enable /
   hx83102_register_read/write.
3. Zero-flash controller: host loads firmware into SRAM every boot.
   hx83102_download_firmware_0f reproduces hx83102ab_firmware_update_0f +
   himax_mcu_write_sram_0f (system reset -> sense_off -> SRAM writes).

## Init sequence (hx83102_control_initialize)
1. Pin config (TWI PB2/PB3, RST PB4, INT PB5 - same as GT9271).
2. Pin reset (RST low 20ms / high 50ms).
3. download_firmware_0f (system reset + sense_off + SRAM load).
4. Release safe mode (raw_out_sel, sorting_mode_en = 0) + sense_on.
5. Status read as bus-liveness check.

## Coordinate format (report @ 0x30)
- Bytes [0 .. 4N-1] : N fingers x 4 (x_hi,x_lo,y_hi,y_lo).
- Byte [4N] : point count (low nibble; 0xFF = no touch).
- N = HX83102_MAX_TOUCH_POINTS = 10 (must match chip HX_MAX_PT).
Current parsing takes the FIRST active finger (single touch, like gt9271;
multi-touch tracking is a TODO). Native coords are scaled to the logical
1440x720 landscape framebuffer and rotated 270 deg (degree0=3).
